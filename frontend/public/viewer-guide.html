문서 뷰어 연동 안내

다른 시스템이 들고 있는 오피스 문서를 웹에서 보기만 하게 해 주는 길이다. 파일을 내려받지 않고, 사용자 PC 에 오피스가 없어도 열린다.

  • 대상 형식: xlsx · docx · hwp · hwpx · pptx
  • 편집·저장·내려받기는 없다. 읽기 전용이다.
  • 문서보안(DRM)이 걸린 문서는 복호화기를 끼운 설치에서만 열린다.

1. 어떻게 도나

[그쪽 시스템] ──① 발급 요청(파일 또는 URL)──▶ [Web Office] ◀─② { "viewUrl": "/v/{토큰}" } ── [사용자] ──③ 그 주소를 연다 ───────────▶ 읽기 전용 화면

① 은 서버끼리 부른다(사용자 브라우저가 아니라). ③ 만 사람이 연다.

2. 발급 요청

POST https://office.example.com/api/view/documents
열쇠는 없다. 부를 수 있는 서버 주소(IP) 로만 가린다. 열려 있는 것은 설정(weboffice.view.callers)에 적어 둔 대역뿐이다. 다른 곳에서 부르면 403 FORBIDDEN_ADDRESS 이고 그 사실이 이력에 남는다. 대역을 늘리려면 이 서버를 운영하는 쪽에 부를 서버 주소를 알려 달라.

방법 (가) — 파일을 그대로 올린다

우리 서버가 그쪽 파일 서버에 못 닿을 때 쓴다.

curl -X POST https://office.example.com/api/view/documents \
  -H "X-WO-API-KEY: 발급받은열쇠" \
  -F "file=@보고서.xlsx" \
  -F "fileName=보고서.xlsx" \
  -F "viewerName=홍길동 책임"

방법 (나) — 파일 주소를 준다

우리 서버가 그 주소로 받아 온다. 호출이 가볍다.

curl -X POST https://office.example.com/api/view/documents \
  -H "X-WO-API-KEY: 발급받은열쇠" \
  -H "Content-Type: application/json" \
  -d '{
        "fileUrl": "https://erp.example.com/files/12345",
        "fileName": "보고서.xlsx",
        "viewerName": "홍길동 책임",
        "systemName": "전자결재",
        "fetchHeaders": { "Authorization": "Bearer ..." }
      }'

fetchHeaders 는 그 주소를 받아 올 때만 쓰고 저장하지 않는다.

응답 (둘 다 같다)

{
  "viewUrl": "/v/26c322a9117a10c794c6f1fab04830dc",
  "expiresAt": "2026-08-20T14:54:41",
  "docType": "SHEET",
  "encrypted": false
}
칸뜻
viewUrl사용자에게 넘길 주소. 앞에 우리 도메인을 붙여 쓴다
expiresAt이 주소를 열 수 있는 시각까지
docTypeSHEET(시트) · DOC(문서) · SLIDE(슬라이드)
encryptedDRM 이 걸려 있던 문서인가. true 면 화면에 워터마크가 얹힌다

보내는 값

값필수설명
fileName필수확장자로 형식을 가린다. 없거나 틀리면 415 다
viewerName권장이력에 "누가 봤나" 로 적힌다. 사번은 보내지 마라 — 받아도 쓰지 않는다
systemName필수부르는 시스템 이름. 이력의 "어느 시스템이 보냈나" 다. 없으면 400
file / fileUrl필수둘 중 하나

3. 수명은 세 겹이다

발급 ──(5분 안에 열어야 함)──▶ 열림 ──(그 창에서 8시간)──▶ 닫힘 └──(문서 데이터는 1시간)──▶ 다시 발급 필요
겹기본값무엇을 재나
보기 토큰5분링크를 처음 열 수 있는 시간. 열리는 순간 죽는다
창 세션8시간연 창에서 새로고침·스크롤이 되는 시간
문서 데이터1시간우리가 변환 결과를 들고 있는 시간

실제로 볼 수 있는 시간은 셋 중 가장 짧은 것이다.

링크는 먼저 연 브라우저 것이 된다. 열리는 순간 그 브라우저에 세션이 생기고, 같은 주소를 다른 창에서 열면 410 이다. 그러니 사용자마다 따로 발급해라. 한 번 발급받아 여러 사람에게 돌리면 맨 처음 사람만 본다.
원본은 보관하지 않는다. 1시간이 지나면 변환 결과도 지운다. 사용자가 다시 보려 하면 그쪽 시스템이 다시 발급하면 된다 — 같은 문서면 대개 0.3초 안에 끝난다(잠깐 캐시가 살아 있으면 변환을 건너뛴다).

4. 오류

HTTPcode무슨 뜻그쪽이 할 일
400MISSING_SYSTEM_NAMEsystemName 을 안 보냄시스템 이름을 실어라
403FORBIDDEN_ADDRESS허용 안 된 주소에서 부름부르는 서버 IP 를 알려 달라
401UNAUTHORIZED열쇠를 따로 받은 시스템인데 틀림대개는 안 쓴다
410TOKEN_EXPIRED
TOKEN_USED		5분이 지났거나 이미 열린 링크다시 발급
413TOO_LARGE파일이 한도(기본 50MB)를 넘음—
415UNSUPPORTED_TYPE우리가 못 여는 형식fileName 확장자 확인
422CONVERT_FAILED파일이 깨졌거나 읽지 못함원본 확인
422DECRYPT_FAILEDDRM 을 풀지 못함문서보안 담당과 확인
502FETCH_FAILEDfileUrl 에서 못 받아 옴주소·인증 헤더·방화벽 확인
503DISABLED뷰어를 잠시 꺼 둠잠시 뒤 다시

응답 본문은 늘 이 모양이다.

{ "code": "UNSUPPORTED_TYPE", "message": "볼 수 없는 형식입니다: 사진.png" }

사용자가 여는 주소(/v/{토큰})에서 문제가 나면 코드 대신 까닭을 적은 안내 화면이 뜬다.

5. 부르는 예시

Java (Spring RestClient)

public String 보기주소(byte[] 파일, String 파일명, String 열람자) {
    var 몸통 = new LinkedMultiValueMap<String, Object>();
    몸통.add("file", new ByteArrayResource(파일) {
        @Override public String getFilename() { return 파일명; }
    });
    몸통.add("fileName", 파일명);
    몸통.add("viewerName", 열람자);
    몸통.add("systemName", "전자결재");

    Map<String, Object> 응답 = restClient.post()
            .uri("https://office.example.com/api/view/documents")
            .contentType(MediaType.MULTIPART_FORM_DATA)
            .body(몸통)
            .retrieve()
            .body(Map.class);

    return "https://office.example.com" + 응답.get("viewUrl");
}

JavaScript (Node)

const 응답 = await fetch('https://office.example.com/api/view/documents', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    fileUrl: 'https://erp.example.com/files/12345',
    fileName: '보고서.xlsx',
    viewerName: '홍길동 책임',
    systemName: '전자결재',
  }),
});
const { viewUrl } = await 응답.json();
window.open('https://office.example.com' + viewUrl);
발급은 서버에서 불러라. 허용된 대역은 적어 둔 서버와 개발자 PC 다 — 사용자 브라우저에서 직접 부르면 그 사람 주소로 나가 막힌다.

6. 붙이기 전에

  1. 부를 서버 주소를 알려 줘라. 이 서버를 운영하는 쪽에 시스템 이름과 그 서버 IP 를 주면 대역에 넣는다. 열려 있는 것은 설정 (weboffice.view.callers)에 적어 둔 대역뿐이다.
  2. URL 방식을 쓸 거면 우리 서버가 그 주소에 닿는지 미리 확인해라(방화벽).
  3. 시스템 이름과 열람자 이름을 보내라. 이력에 남아야 "어느 시스템이 · 누구에게 보여 줬나" 를 나중에 답할 수 있다. 시스템 이름은 필수다.
  4. 사용자마다 발급해라. 링크 하나를 여럿에게 돌리면 맨 처음 사람만 본다.

7. 안 되는 것

  • 편집·저장·주석 — 읽기 전용이다.
  • 내려받기·인쇄 전용 화면 — 없다.
  • 링크 재사용 — 한 번 열리면 그 창의 것이다.
  • 화면 촬영 막기 — DRM 문서의 워터마크는 억제이지 차단이 아니다.

8. 이력은 어디서 보나

관리자 화면 /admin/views — 누가 · 언제 · 어느 문서를 봤는지, 무엇이 실패했는지, 하루 몇 건인지 본다. 관리자로 지정된 계정로 등록된 사람만 들어간다.
